# CLAUDE.md – Cuộc đua Paris

Browser 3D race game (1 leg in central Paris) + Host screen. Full spec: `docs/SPEC.md` (§17 overrides earlier sections). Never edit `docs/SPEC.md` (only the orchestrator appends user decisions to §17).

## Stack
- Everything on Cloudflare: Workers Static Assets (client build) + Worker (API) + one SQLite-backed Durable Object `RaceRoom` per race + R2 bucket `MEDIA` + secret `HOST_PASSWORD`. No Node server, no Colyseus, no VPS.
- npm workspaces, TypeScript strict (`tsconfig.base.json`, TS 7 native `tsc`), Vitest, Vite, wrangler, Playwright (`playwright-core` + system Chrome).
- Client (from Phase 1): Three.js + @dimforge/rapier3d-compat. Leg schema: zod in `/shared` (Phase 7).

## Coordinates
- 1 unit = 1 m. Origin (0,0,0) = Concorde obelisk 48.86548, 2.32115. X = East, Z = −North, Y = up.
- Use only `latLonToWorld` / `worldToLatLon` from `shared/src/projection.ts`; `RACE_BBOX` / `ORIGIN` in `shared/src/constants.ts`.
- Y is relative: y = DEM − DEM(ORIGIN) (obelisk base y = 0). `carveRiver` then drops the Seine to ≈ −5.5 m (bed −8.5) and lifts the quays to ≈ +1.5 m; always read heights from the carved grid (`heightAt`).

## Server principles
- The Durable Object is authoritative (clues, answers, timing, penalties, ranking, bike claims).
- Leg content (clues, answers) never goes into static assets or the client bundle; answers are never sent to the client (client sends an answer, gets right/wrong); R2 media (private bucket) is served by the Worker only to teams that have unlocked that clue.
- Write every important change to DO SQLite BEFORE acking the client; rebuild all state from SQLite on DO start.
- No heavy compute in the DO: road graph / A* / bike corridors are computed in the Host browser; the DO only picks randomly from the submitted candidates.

## Cloudflare quota budget (SPEC §3, mandatory)
- Client sends position 5 Hz, only on change, as compact number arrays rounded to cm (20 WS messages = 1 billable request).
- Server batches all positions into 1 broadcast per tick at 5 Hz.
- SQLite batched writes: last positions of ALL teams = 1 upserted row every 2 s; replay log 1 row per 10 s; race events immediately.
- Budget for a 2 h / 20-team race: < 40,000 billable requests and < 20,000 SQLite rows written.
- DO Alarms for periodic bike spawning; no loop when nobody is connected.
- Each static asset ≤ 25 MB (Draco/Meshopt, KTX2); big media on R2.
- Host debug view shows estimated counters: WS messages received, SQLite rows written.

## Input (SPEC §17: PC Windows + macOS only)
- No Ctrl / Alt / Option / Cmd / Win as gameplay keys; no F-key as the only binding; never F5 / F11 / F12.
- Bindings by `KeyboardEvent.code` in `client/src/config.ts` (Phase 1), several keys per action. Key table: SPEC §17.2. Bike (Phase 4): F take/mount/dismount, W pedal, S brake/reverse, A/D steer, R bell, C camera. Debug-only (F3 open): V free-fly, N road graph overlay. Louvre room (Phase 8B): F at the box enters (≤ `louvreRoom.enterReach` m), inside F = the faced button (pick / unpick), the lock button, or the door (out).

## Commands
- `npm run dev` – client Vite dev server.
- `npm run dev:worker` – builds client, then `wrangler dev` on :8787 (static assets + API + DO + SQLite + R2 locally). Copy `worker/.dev.vars.example` → `worker/.dev.vars`.
- `npm run build` – typecheck everything + client build + `wrangler deploy --dry-run` bundle check. Run it from the root: the worker build needs `client/dist`.
- `npm test` – Vitest in `scripts/` + every workspace.
- `npm run fetch-map` – run once: `fetch-osm` (Overpass, 500 m tiles + one global query for relations / water / parks / arrondissements, resumable, ≥ 2 s between requests; `--out <dir>`) → raw JSON in `.cache/osm/` (gitignored: `tiles/<ix>_<iz>.json`, `global.json`, `skyline.json` (La Défense towers), `index.json`); then `fetch-dem` (AWS terrarium z14, PNGs cached in `.cache/dem/`) → `client/public/data/elevation.bin` + `elevation.json` (committed). Tile (ix, iz) covers world x ∈ [500·ix, 500·ix + 500), z ∈ [500·iz, 500·iz + 500).
- `npm run build-chunks` – `.cache/osm` → `client/public/data/chunks/<i>_<j>.json` (v 2, 250 m, parsed OSM facts only, no names except road names; landmark outlines carry their `building:part` + zone nodes) + `index.json` + `water.json` + `skyline.json`. Deterministic; the output IS committed (the build needs it), rerun only when the extraction changes. Defaults/tuning live in the builders + `config.ts`, not in the data.
- `npm run process-assets` – `.cache/assets` (approved originals, never committed) → `client/public/models/*.glb` (Meshopt; incl. `npc-vehicles.glb`, `npc-peds.glb` (Rocketbox, atlas), `npc-ped-anims.glb`; incl. player.glb + player-anims.glb, UAL clips renamed to the UBC bones) + `client/public/credits.json` (the in-game "Ghi nguồn" panel). Deterministic, output committed. Positional names build only those models: `-- --assets <dir> player player-anims`. Phase 8B `louvre`: `<dir>/louvre/manifest.json` `{seed, items}` (outside the repo; the only real-name ↔ art-NN link) → `client/public/art/art-NN.{webp,glb}` (WebP ≤ 300 KB, scans simplified to fit, total ≤ 8 MB) + `<dir>/louvre/credits-snippet.json` (outside the repo); current input: `-- --assets .cache/assets-louvre-run louvre` (docs/LEG_FORMAT.md §7.5, TODO.md Phase 8B).
- `npm run screenshot [preset]` – headless Chrome → `screenshots/<preset>.png`; fails on console errors; logs `__STATS__` {calls, triangles, chunks, colliders, geometries}. Pages set `window.__READY__ = true` once rendered and settled (game: ChunkManager idle + ≥ 3 frames); presets (topdown, etoile, champs, eiffel, street, seine, edge, player, debug; by name only: `lm-<landmark id>`, `leg-L1`…`leg-L6`, `p3-*` player views (a bare prefix like `p3` runs the group), `p6-*` / `p7-*` / `p8-*` offline race stand-ins (`p8-card-*`, `p8-book-media`, `p8-box-yaw`, `p8-box-branch`, `p8-media-offline`, `p8-host`; `p8b-*`: `p8b-room`, `p8b-room-button`, `p8b-room-lock` (countdown), `p8b-card-louvre[-small]`, `p8b-feed[-small]`, `p8b-credits`, `p8b-host`), several per run) live in `scripts/screenshot.ts`. `SCREENSHOT_PORT=<n>` picks the Vite port (default 5174); any page: `-- --path "/preview.html?…" --name <file>`.
- Preview harness `/preview.html` (dev server only): builds a few chunks on the main thread without streaming/fog. `at=<lat>,<lon>&r=<m>` or `chunks=<key>,…` or `fixture=1`; `only=terrain,buildings,roads,bridges,vegetation,props,landmarks`; `carve=1`, `water=1`, `cam=…`.
- The game starts in player mode (spawn `playerSetup.spawn`, Concorde). Client URL overrides: `?cam=x,y,z,yawDeg,pitchDeg` = spectator (free-fly only, no body; yaw 0 = north / −Z), `?debug=1` (F3 overlay on); HUD: `?gps=x,z` (waypoint), `?map=1`, `?menu=1`, `?respawn`; NPC: `?npc=0` off (ride-check, physics presets), `npcSeed`, `npcDensity`, `npcZone=x,z,r[;…]` (exclusion circles), `npcTest=car:<kind>@x,z,yaw`; auto-density is off with `wait` or headless; `?player[=x,z,yawDeg]&camMode=&orbit=&action=&autoMove=&jump&wait=` (docs/plans/phase3.md §7); race stand-ins (offline): `?boxes=step[|branch],x,z[,opened][,yawDeg];…` (yawDeg 0 = box front north, the default; `&mat` = Pit Stop mats), `?card=<kind>&full`, `?book[=media]`, `?lock=<s>` (RaceHud.demo). Race keys: `Enter` reopens the current card, `Tab` the Sổ; a card / the Sổ releases the mouse (links, images, answer box clickable) and closing it locks it again. `V` while the F3 panel is open: player ⇄ free-fly. DEV only: `window.__GAME__.{fly, player}` for scripts.
- `npm run build-graph` – `.cache/osm` → `shared/data/roadgraph.json` (v 1, format in `shared/src/graph/types.ts`: dm nodes, ways `[kind, flags, lanes, name, widthDm, layer, …nodes]`, junctions / crossings / signals / bikeParking; sidewalks, crossings, pedestrian-area outlines kept; tunnels / covered / underground / indoor dropped). Deterministic, committed, ≈ 2.2 MB; prints nodes / edges / walk components. Read via `@race/shared/graph` (`RoadGraph.decode`, `nearestNode` snaps to the main walk component, `shortestPath` A*, `corridorEdges`, `surfaceAt`); client/Host fetch it as a static asset (`geo/roadGraph.ts`), the worker never imports it. Preview overlay: `/preview.html?…&graph=1&route=lat,lon,lat,lon`; in game `?graph=1` or N with the F3 panel open.
- `npm run ride-check` – scripted headless play with real keys (walk → bike 300 m on the A* car route → brake → crash → remount → quay stairs → swim → [opt-in `RIDE_ONLY=3`: quay stairs → swim → back onto the steps from the river side → up to the quay]); prints walk/bike max speed, ratio, lean, heap, rider+bike draw calls; exits 1 on a failed check or console error. `SCREENSHOT_PORT=<n>`, `RIDE_ONLY=1|2|3`.
- `npm run leg:check -- <leg.json>` – validates a leg file (zod + rules + map checks: radius 15–40 m, inside RACE_BBOX, not inside a building, reachable on foot, bike-rack typos, answer-leak scan of client/public + dist incl. `referenceAnswers`; a louvre step: the 23-artwork table (id / type / file / size / licence, never names), art-NN file rules, answer-code leaks, credits.json / art bytes scanned for names; leak scan in step order, the two Lựa chọn kép branches cross-scanned; `[CHƯA NHẬP` = blank) with Vietnamese messages and a picture/links per point (box heading, "hòm nhánh X", `boxes=…,<yawDeg>` link) + the list of `r2:` images to upload on the Host page; warns on https links to image files; format for the organiser in `docs/LEG_FORMAT.md`; the real leg stays OUTSIDE the repo and is loaded on the Host page ("Nạp chặng từ file"). Bundled demo/test legs: `worker/legs/paris-demo.json`, `worker/legs/test/*.json` (fake content marked (GIẢ)).
- `npm run dev:api` – wrangler dev for the API / DO (Vite proxies `/api` + WebSocket to it); real race URL `/?race=<id>` (offline test world: `?offline=1` or no `?race=`; experimental URL params are ignored inside a real race). `npm run sim` – bot teams over WebSocket (≤ `--speedup 2`; `--leg <id|file>` plays a whole leg: bots accept / answer / choose + one switches branch, a Host bot approves and penalizes once, penalties cut to 6 / 12 s; a louvre step: one wrong lock, the countdown, then the right 5; `--help`) printing request / SQLite-row stats vs the SPEC §3 budget. DO tests use `createTestHarness` (wrangler), not `@cloudflare/vitest-pool-workers`.
- Later: `deploy` (Phase 12; `sim` full-run scenarios Phase 11).

## Workflow
- Before each phase: read `docs/SPEC.md` + this file, write a short plan, list packages to install.
- `npm run build && npm test` must pass after each phase; commit `feat(phaseN): …`.
- Anything not done (missing model, API key…) → placeholder + `TODO.md`. Never silently drop a requirement.
- All tunables in `client/src/config.ts` or the leg config; never hard-code speeds etc. elsewhere.
- UI / player & Host docs / README / TODO in Vietnamese with diacritics; code, identifiers, files, APIs in English.
- Visual check via `npm run screenshot`, then look at the PNG.
- Minimal code; deliberate shortcuts get `// ponytail: <ceiling>, <upgrade path>`.
- Do not leave `wrangler dev` / `workerd` / `vite` running.
